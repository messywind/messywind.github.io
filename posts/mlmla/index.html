MLA（Multi-head Latent Attention）详细笔记

多头潜在注意力，DeepSeek-V2 提出、V3/R1 沿用的核心注意力结构。 本笔记基于 DeepSeek-V2/V3 的 MLA 图解整理，面向初学者，同时覆盖面试要点。

0. 一句话理解

MLA = 把每个 token 的 K、V 压缩成一个很小的「潜在向量」存进 KV Cache，需要用的时候再「解压」回来；并且配一套独立的 RoPE 位置信息。

它要解决的核心痛点只有一个：推理时 KV Cache 太占显存。MLA 用「低秩压缩 + 矩阵吸收」两个技巧，把 KV Cache 砍到原来的几十分之一，同时几乎不掉点。

1. 背景：为什么需要 MLA？

1.1 先回顾 KV Cache 是什么

自回归生成时，每生成一个新 token，都要拿它的 Query 去和前面所有 token 的 Key、Value 做注意力。 如果每一步都重算前面所有 token 的 K、V，会有大量重复计算。所以工程上把已经算好的 K、V 缓存下来，这就是 KV Cache。

代价是：序列越长，缓存越大。它直接决定了：

  • 单卡能放下多长的上下文；
  • 能并发服务多少个请求（batch size）；
  • 长文本推理的速度（显存带宽往往是瓶颈）。

1.2 标准 MHA 的 KV Cache 有多大

标准多头注意力（MHA）需要为每个头都缓存一份完整的 K 和 V。

以本笔记的配置（128 个头、每个头维度 128）为例，每个 token 要存：

1
2

KV Cache(MHA) = 2 (K和V) × 头数 × 每头维度
             = 2 × 128 × 128 = 32768 个数 / token

序列一长，这个数字乘以序列长度，显存就爆了。

1.3 已有的折中方案：MQA / GQA

方法 思路 KV Cache 效果
MHA（标准多头） 每个头独立的 K、V 最大 效果最好
MQA（Multi-Query） 所有头共享一份 K、V 最小 省得多，但掉点明显
GQA（Grouped-Query） 把头分成几组，组内共享 K、V 中等 MHA 和 MQA 的折中
MLA K、V 压缩成低维潜在向量再缓存 很小 几乎不掉点，还更省

MQA/GQA 是通过「减少 K、V 的份数」来省显存，本质是牺牲表达能力。 MLA 换了个思路：份数不减，但把每份压缩到极低维度再存。

1.4 MLA 的核心思想

缓存的不是完整的 K、V，而是一个被压缩过的「潜在向量」 $c^{KV}$（512 维），用的时候再通过一个上投影矩阵解压回完整的 K、V。

而且后面会看到，靠「矩阵吸收」技巧，连解压这一步都可以省掉——直接在压缩空间里算注意力。

2. MLA 的核心机制：低秩压缩（Low-Rank Compression）

「低秩」可以这样直观理解： 一个 token 的完整 K（128×128 维）信息其实有很多冗余，并不需要那么多维度就能表达。 我们可以先用一个降维矩阵把高维 hidden state 压成一个小向量（如 512 维），缓存这个小向量； 真正要用 K、V 时，再用一个升维矩阵把它还原回去。

MLA 对 K/V 和 Q 都做了这种「先降维（down）、再升维（up）」的压缩：

  • KV 压缩：是为了省 KV Cache 显存（这是主目的）。
  • Q 压缩：Q 不需要缓存，压缩它主要是为了省训练时的参数量和激活显存。

记住几个关键符号：

符号 含义 维度
$h_t$ 第 t 个 token 的输入隐藏状态 7168
$c_t^{KV}$ KV 的压缩潜在向量（要缓存） 512
$k_t^{R}$ 解耦 RoPE 的 Key（要缓存，所有头共享） 64
$c_t^{Q}$ Q 的压缩潜在向量（不缓存） 1536

🔑 KV Cache 只需要存 $c_t^{KV}$(512) + $k_t^R$(64) = 576 个数 / token。 对比 MHA 的 32768，缩小约 57 倍！

3. 一个绕不开的难题：RoPE 与压缩的矛盾 → 解耦 RoPE

这是 MLA 设计里最精妙、也是面试最爱问的一点。

3.1 矛盾在哪

MLA 想做的优化是「矩阵吸收」（见第 6 节）：把 K 的升维矩阵预先合并到 Q 上，这样推理时不用真的把 $c^{KV}$ 解压成 K。

但 RoPE 是一个跟「位置」相关的旋转操作，它作用在 Q、K 上时，旋转的角度取决于 token 的位置 $t$。 如果 K 里带了 RoPE，那「Q 升维矩阵 × K 升维矩阵」这个乘积里就夹着一个随位置变化的旋转矩阵，没法在推理前提前合并（吸收）——因为每对 (i, j) 位置的旋转都不一样。

一句话：RoPE 的位置依赖性，破坏了矩阵吸收所需要的「可提前合并」性质。

3.2 DeepSeek 的解法：解耦 RoPE（Decoupled RoPE）

把 Query 和 Key 都拆成两部分：

  • nope 部分（no positional embedding）：不带位置信息，参与低秩压缩 + 矩阵吸收。维度 128。
  • rope 部分：专门承载 RoPE 位置信息，单独走一条小通路。维度 64。

最终的 Q、K 是两部分拼接起来的：

$$q_{t,i} = [\,q_{t,i}^{C}\,;\,q_{t,i}^{R}\,] \qquad k_{t,i} = [\,k_{t,i}^{C}\,;\,k_{t}^{R}\,]$$
  • 上标 $C$ = content（nope，内容部分）
  • 上标 $R$ = RoPE（位置部分）

注意力打分时，两部分点积自然相加：

$$q_{t,i}^T k_{j,i} = \underbrace{q_{t,i}^{C}\cdot k_{j,i}^{C}}\_{\text{nope，可被吸收}} + \underbrace{q_{t,i}^{R}\cdot k_{j}^{R}}_{\text{rope，单独算}}$$

这样 nope 部分可以享受矩阵吸收的全部好处，rope 部分单独处理位置，互不干扰。

3.3 两个重要细节

  1. RoPE Key 所有头共享：$k_t^R$ 只有一份（64 维），不是每个头一份。所以 KV Cache 里只加 64 维。图中 KV rope 出来后要 Repeat 广播到每个头。
  2. 缩放因子要带上 rope 维度：注意力分母是 $\sqrt{d_h + d_h^R} = \sqrt{128 + 64}$，因为拼接后总维度变大了。

缓存账本：每个 token 只存 512 + 64 = 576 维。 这就是 MLA 省显存的全部秘密所在。

6. 矩阵吸收（Matrix Absorption）—— 推理加速核心，对应图 2

第 4 节里，推理时我们好像还是把 $c^{KV}$ 解压回了完整的 K、V。 矩阵吸收告诉我们：其实没必要解压，可以直接在 512 维的压缩空间里算注意力。原理是把升维矩阵提前合并进相邻的矩阵。

6.1 K 矩阵的吸收

只看 nope 部分的注意力打分，逐步展开：

$$ \begin{aligned} \text{Attention} &= q_t^C \, k_t^{C\,T} \\ &= (c_t^Q W^{UQ})(c_t^{KV} W^{UK})^T \\ &= c_t^Q \, W^{UQ} W^{UK\,T} \, c_t^{KV\,T} \\ &= c_t^Q \,\underbrace{(W^{UQ} W^{UK\,T})}_{\text{提前合并}}\, c_t^{KV\,T} \\ &= c_t^Q \, W^{UQK} \, c_t^{KV\,T} \end{aligned} $$

维度变化（每个头）：

1
2
3

W^UQ  ∈ [1536, 128, 128]
W^UK  ∈ [512, 128, 128]
W^UQ × W^UK^T  ∈ [1536, 128, 512]  =  W^UQK   ← 合并成一个新矩阵

含义：把「K 的升维矩阵 $W^{UK}$」吸收进了 Query 那一侧。于是：

  • 推理时不需要把缓存的 $c^{KV}$ 还原成 K；
  • 直接拿 $c_t^Q$（经 $W^{UQK}$ 变换后）和缓存的 $c_j^{KV}$ 做点积即可。
  • $c^{KV}$ 同时扮演了「被缓存的 Key」的角色。

6.2 V 矩阵的吸收

同理看输出侧（注意力加权 V 之后再过输出投影 $W^O$）：

$$ \begin{aligned} \text{Output} &= (c_t^{KV} W^{UV})\, W^O \\ &= c_t^{KV}\,\underbrace{(W^{UV} W^O)}_{\text{提前合并}} \\ &= c_t^{KV}\, W^{UVO} \end{aligned} $$

维度变化（每个头）：

1
2
3

W^UV ∈ [512, 128, 128]
W^O  ∈ [128, 128, 7168]
W^UV × W^O  ∈ [512, 128, 7168]  =  W^UVO   ← 合并成一个新矩阵

含义：把「V 的升维矩阵 $W^{UV}$」吸收进了输出矩阵 $W^O$。于是：

  • 注意力的加权求和直接在 512 维潜在空间里完成（对 $c_j^{KV}$ 加权）；
  • 最后用 $W^{UVO}$ 一次性投影回 7168 维。
  • $c^{KV}$ 同时又扮演了「被缓存的 Value」的角色。

6.3 最终形式

把两次吸收合起来，整个 MLA 在推理时可以写成一个紧凑式子：

$$\text{Output} = \mathrm{softmax}\!\left(\frac{h_t\, W^{DQ}\, W^{UQK}\, c_t^{KV\,T}}{\sqrt{d}}\right) c_t^{KV}\, W^{UVO}$$

注意：上式是 nope 部分的简化示意，实际还要加上 rope 部分的打分 $q^R \cdot k^R$。完整缩放因子是 $\sqrt{d_h + d_h^R}$。

6.4 为什么矩阵吸收这么关键

  1. 省显存：缓存里只有 512+64 维的 $c^{KV}$、$k^R$，永远不需要展开成 128×128 的完整 K、V。
  2. 省计算/带宽：解码时读取的缓存量极小，而显存带宽通常是长文本推理的瓶颈。
  3. 不掉点：吸收只是矩阵结合律的等价变形，数学上完全等价，不损失精度。
  4. 这也正是为什么需要解耦 RoPE——只有 nope 部分能被吸收，带位置的 rope 部分必须单独留出来。

7. MLA vs 其他注意力对比

维度 MHA MQA GQA MLA
K/V 份数 每头一份 全共享一份 分组共享 每头一份（但压缩）
省显存手段 无 减份数 减份数 低秩压缩
每 token 缓存（本配置） 32768 256 中等 576
效果 基准 掉点明显 接近 MHA ≈MHA 甚至更好

MLA 的卖点：用 GQA 级别（甚至更低）的缓存开销，拿到 MHA 级别的效果。

8. 面试高频问答

Q1：MLA 是用来解决什么问题的？ A：推理时 KV Cache 占显存太大，限制了上下文长度和并发。MLA 通过对 K、V 做低秩压缩，把每 token 缓存从几万维降到几百维。

Q2：MLA 缓存的到底是什么？ A：只缓存压缩后的潜在向量 $c_t^{KV}$（512 维）和一份所有头共享的 RoPE Key $k_t^R$（64 维），共 576 维/token。完整的 K、V 在需要时由升维矩阵恢复。

Q3：为什么要搞「解耦 RoPE」？ A：因为 MLA 想用「矩阵吸收」省掉 K、V 的解压步骤，但 RoPE 是位置相关的旋转，夹在升维矩阵中间就没法提前合并。于是把 Q、K 拆成 nope（参与吸收）和 rope（单独承载位置）两部分。

Q4：什么是矩阵吸收？为什么不掉点？ A：利用矩阵乘法结合律，把 K 的升维矩阵合并进 Query 侧（$W^{UQK}$）、把 V 的升维矩阵合并进输出侧（$W^{UVO}$）。这样推理时直接在压缩空间算注意力，无需展开 K、V。因为是等价变形，精度无损。

Q5：MLA 和 GQA 的本质区别？ A：GQA 靠「减少 K、V 的份数」省显存（牺牲表达力）；MLA 份数不减，靠「把每份压缩到低维」省显存，并能用吸收技巧进一步免解压，所以效果更接近 MHA。

Q6：Q 为什么也要压缩？ A：Q 不进 KV Cache，压缩它不是为了推理省显存，而是为了减少训练时的参数量和激活显存。

Q7：注意力缩放因子为什么是 $\sqrt{d_h + d_h^R}$？ A：因为最终的 Q、K 是 nope(128) 和 rope(64) 拼接而成的，总维度是 192，缩放要按拼接后的总维度算。

9. 关键记忆点（速记卡）

  • 目标：砍 KV Cache 显存。
  • 手段：K/V 低秩压缩 → 缓存 $c^{KV}$(512) + 共享 $k^R$(64)，共 576/token。
  • 两次降升维：
    • Q：h → c^Q(1536) → q(192/头)
    • KV：h → c^KV(512) → k^C/v^C(128/头)；外加 h → k^R(64)。
  • 拼接结构：$q=[q^C;q^R]$、$k=[k^C;k^R]$，nope=128、rope=64。
  • 解耦 RoPE：rope 单独走，nope 才能被吸收；RoPE Key 全头共享。
  • 矩阵吸收：
    • K 侧：$W^{UQ}W^{UK,T} = W^{UQK}$（K 升维吸进 Q）
    • V 侧：$W^{UV}W^{O} = W^{UVO}$（V 升维吸进输出）
    • 效果：推理直接在 512 维空间算注意力，免解压、不掉点。
  • 一句话：压缩存、吸收算、效果不输 MHA。
