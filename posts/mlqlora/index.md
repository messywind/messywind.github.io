## 1. 量化基础

### 1.1 定义与收益

量化 = 用低比特数据类型近似表示高精度数值。

| 精度 | 每参数字节 | 7B 权重显存 |
|---|---|---|
| FP32 | 4 B | 28 GB |
| FP16 / BF16 | 2 B | 14 GB |
| INT8 | 1 B | 7 GB |
| INT4 / NF4 | 0.5 B | 3.5 GB |

**两大收益(面试必答第二点是加分项):**
1. 显存:4-bit 是 FP16 的 1/4
2. 推理速度:LLM decode 阶段是 **memory-bound**,权重读取带宽是瓶颈,量化直接提升 tokens/s

&gt; 💡 Agent 岗关联话术:Agent 场景 token 消耗巨大(多轮工具调用、长上下文、多 Agent 通信),推理成本敏感度远高于普通对话产品,量化是降本增效的核心手段。

### 1.2 基本原理:absmax 对称量化

以 FP32 → INT8 为例,INT8 范围 [-127, 127]:

```
量化:   X_int8 = round( (127 / absmax(X)) · X )
反量化: X_fp32 ≈ X_int8 / c ,其中 c = 127 / absmax(X) 为量化常数(scale)
```

**手算示例**:张量 `[0.1, -0.5, 2.0, 0.3]`,absmax=2.0,c=63.5

| 原值 | 量化 | 反量化 | 误差 |
|---|---|---|---|
| 0.1 | 6 | 0.094 | 有 |
| -0.5 | -32 | -0.504 | 有 |
| 2.0 | 127 | 2.000 | 无 |
| 0.3 | 19 | 0.299 | 有 |

另有**零点非对称量化(zero-point)**:引入偏移量,适合非对称分布(如 ReLU 后全正),区间利用率更高。

### 1.3 核心痛点:离群值(Outliers)→ 分块量化

**逻辑链(必须顺,是双重量化的引子):**

```
离群值 (如 [0.1, -0.5, 100.0, 0.3])
   ↓ absmax 被撑大 → c = 127/100 = 1.27
小数值被压成 0 (0.1→0, 0.3→0),信息大量丢失
   ↓ 解决方案
分块量化 (Block-wise): 每 64 个数一块,各块独立量化常数
   ↓ 一个离群值只污染所在块
   ↓ 代价
每块要额外存一个量化常数 → block 越小越精细,但常数开销越大
   ↓ 这个 trade-off 正是 QLoRA「双重量化」的动机
```

LLM 权重/激活中确实存在离群值(LLM.int8() 论文专门研究)。

### 1.4 PTQ vs QAT

| | PTQ 训练后量化 | QAT 量化感知训练 |
|---|---|---|
| 时机 | 训练完直接量化 | 训练中模拟量化误差 |
| 成本 | 低、快 | 高 |
| 效果 | 够用 | 更好 |
| 代表 | GPTQ、AWQ | — |
| 工业界 | **LLM 部署主流** | 少用 |

QLoRA 定位:基座是 PTQ(冻结 4-bit),但通过全精度 LoRA adapter 训练来补偿量化损失。

### 1.5 部署侧加分知识(Agent 工程岗差异化)

- **GPTQ**:基于二阶信息(Hessian)逐层最小化量化误差
- **AWQ**:激活感知——少数「显著权重」对应大激活值,按激活分布做 per-channel 缩放保护它们;无需反向传播,量化快;vLLM 等框架支持好,部署主流之一
- **W4A16 记号**:权重 4-bit、激活 16-bit;只量化权重是主流;激活量化(W8A8,如 SmoothQuant)难在激活离群值更严重
- **KV Cache 量化**:Agent 长上下文场景 KV Cache 是显存大头,可量化到 INT8/FP8(vLLM 支持)——贴合 Agent 痛点的加分点

可以不深究:分位数量化数学推导、QAT 的 STE、kernel 实现。坦承「没深入 kernel 层」比硬编好。

## 2. QLoRA

### 2.1 动机:LoRA 和 QLoRA 各省哪块显存(易混淆,必分清)

| 显存组成 | LoRA 省了吗 | QLoRA 额外省了吗 |
|---|---|---|
| 可训练参数 | ✅(只有 A、B) | 相同 |
| 梯度 | ✅ | 相同 |
| 优化器状态 | ✅ | 相同(&#43;分页防尖峰) |
| **基座权重** | ❌ 仍需 FP16 全量加载 | ✅ **NF4 存储,降到 1/4** |
| 激活值 | ❌ | ❌(相同) |

**标准话术**:LoRA 省的是可训练参数、梯度、优化器状态;基座权重仍要 FP16 加载(7B=14GB)。QLoRA 把冻结基座量化到 4-bit 存储(7B≈3.5GB),BF16 只训 LoRA adapter,单张 24G 卡可微调 7B~13B。论文成果:单张 48G 卡微调 65B(Guanaco)。

### 2.2 三大核心技术(30 秒必答版)

#### ① NF4(4-bit NormalFloat)

- 问题:INT4 均匀格点,隐含假设数据均匀分布;但预训练权重近似**零均值正态分布** N(0, σ)
- 方案:**分位数量化**——按标准正态分布分位数放置 16 个格点,归一化到 [-1, 1]
- 效果:0 附近格点密、两端疏,匹配权重分布;论文证明对正态数据是**信息论最优**的 4-bit 类型
- 细节:格点非对称设计,保证 **0 能被精确表示**
- 使用:每 block 权重先除以块内 absmax 归一化到 [-1,1],再映射到最近 NF4 格点

```
INT4 (均匀):  |--|--|--|--|--|--|--|--|--|--|--|--|--|--|--|
NF4 (分位数): |----|---|--|-|-|||.|||-|-|--|---|----|
                            ↑ 0 附近密集
```

#### ② 双重量化(Double Quantization)

```
第一层: 权重 → NF4, block=64, 每块产生 FP32 量化常数 c₂
        开销 = 32 bit / 64 = 0.5 bit/参数 (相对 4-bit 是 12.5%,不小)
第二层: c₂ (FP32) → FP8, block=256, 产生二级常数 c₁ (FP32)
        开销 = 8/64 &#43; 32/(64×256) ≈ 0.125 &#43; 0.002 ≈ 0.127 bit/参数
```

每参数省约 0.373 bit,65B 模型省约 3GB。

#### ③ 分页优化器(Paged Optimizers)

- 机制:NVIDIA 统一内存(Unified Memory),优化器状态分配在分页内存;显存尖峰(如长序列激活暴涨)时自动换页到 CPU,类似 OS 虚拟内存
- ⚠️ 话术要点:是**防尖峰 OOM 崩溃**,不是降低平均显存占用

### 2.3 计算流程(高频、区分度最大)

**核心:存储用 NF4,计算用 BF16(存储与计算解耦,GPU 无 4-bit 矩阵乘硬件)**

```
前向 (逐层):
  Y = X · dequant(W_NF4) &#43; X · A · B
        ↑ 两级反量化: c₁ 恢复 c₂ → c₂ 恢复权重 → BF16
        ↑ 算完即丢,BF16 权重不驻留显存
        LoRA 分支 A、B 本身 BF16,正常计算

反向:
  梯度需穿过冻结量化权重传给 LoRA (链式法则含 Wᵀ 项)
  → 反向传播也要反量化 (⭐主动说出这点基本赢下这一问)
  基座权重梯度不计算、不存储,只有 A、B 更新
```

**Q: QLoRA 比 LoRA 快还是慢?**
慢。动态反量化是纯增计算开销,训练慢约 20%~30%,换显存降到约 1/3。**时间换空间**。

**Q: 为什么计算用 BF16 不用 FP16?**
BF16 指数位与 FP32 相同(8 位),动态范围大,不易上/下溢,无需 loss scaling,训练稳定;代价是尾数精度低但对 DL 足够。

### 2.4 部署路径(Agent 岗特色问法)

⚠️ 不能把 BF16 的 ΔW=BA 直接加到 NF4 权重上(精度不匹配)。

```
路径 A (merge 部署):
  NF4 基座 → 反量化回 BF16 → merge (W &#43; BA) → 全精度模型
  → 按需再做一次推理量化 (AWQ/GPTQ) → vLLM/SGLang 服务化

路径 B (不 merge, multi-LoRA serving): ⭐强加分项
  推理框架直接挂载 adapter (vLLM 支持 multi-LoRA)
  → 一个基座配多个领域 adapter,共享基座省显存
  → Agent 平台实用场景: 不同工具域各训一个 adapter
```

**Q: 量化有损,为何 QLoRA 能追平 16-bit 全量微调?**
LoRA adapter 全精度训练,可学到对量化误差的补偿。论文关键实验条件:adapter 加到**所有线性层**而非只加 attention 的 Q/V——这也是实操默认配置(`target_modules=&#34;all-linear&#34;`)。

## 3. 实操细节(证明真训过)

```python
from transformers import BitsAndBytesConfig
import torch

bnb_config = BitsAndBytesConfig(
    load_in_4bit=True,
    bnb_4bit_quant_type=&#34;nf4&#34;,              # NF4 而非 fp4
    bnb_4bit_use_double_quant=True,          # 双重量化
    bnb_4bit_compute_dtype=torch.bfloat16,   # 计算精度 (忘设默认 fp32, 又慢又易出问题)
)
```

配套要点:
- 加载后调用 `prepare_model_for_kbit_training()`(处理 layernorm 精度、embedding 梯度等)
- LoRA 超参:r=16~64 常用,alpha 一般取 r 的 2 倍
- 学习率:QLoRA 不算敏感,2e-4 常见起点
- 踩坑话术:梯度检查点需配合 `use_reentrant=False`;bf16 下 loss 不降先查 `compute_dtype` 是否忘设

## 4. 面试速查表(全部能脱口而出 = 达标)

| 检查项 | 关键词 |
|---|---|
| 量化收益 | 显存 1/4、memory-bound、decode 提速 |
| 离群值问题 | absmax 被撑大 → 分块量化 → 每块存常数 |
| NF4 | 正态分位数格点、0 附近密、0 可精确表示、信息论最优 |
| 双重量化 | 0.5 bit → 0.127 bit/参数,65B 省约 3GB |
| 分页优化器 | 防显存尖峰 OOM,非降平均 |
| 计算流程 | 存 NF4 算 BF16、动态反量化、算完即丢、**反向也要反量化** |
| 速度 | 比 LoRA 慢 20~30%,时间换空间 |
| LoRA vs QLoRA 省什么 | LoRA 省参数/梯度/优化器,QLoRA 额外省基座权重 |
| 部署 | 反量化 merge → 再 PTQ;或 multi-LoRA serving |
| 部署量化 | GPTQ(Hessian)、AWQ(激活感知缩放)、W4A16、KV Cache 量化 |
| BF16 原因 | 指数位同 FP32、动态范围大、无需 loss scaling |

## 5. 面试问答链(按真实追问顺序)

**Q1: LoRA 已经很省了,为什么还需要 QLoRA?**
→ 分清各省哪块显存(见 2.1 表格),QLoRA 补上基座权重这块最大的。

**Q2: QLoRA 三大核心技术?**
→ NF4 / 双重量化 / 分页优化器,各一句话(见 2.2)。

**Q3: 4-bit 权重怎么参与计算?**
→ 存算解耦、动态反量化、算完即丢、反向也要反量化(见 2.3)。

**Q4: 比 LoRA 快还是慢?**
→ 慢 20~30%,时间换空间。

**Q5: 训完怎么部署?**
→ 路径 A merge &#43; 再量化;路径 B multi-LoRA serving(Agent 平台场景加分)。

**Q6: 量化有损为何能追平全量微调?**
→ 全精度 adapter 补偿量化误差 &#43; all-linear 加 adapter。
